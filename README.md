# GCS Master Library Data

GURPS[^1] Character Sheet (GCS) is a stand-alone, interactive character sheet editor that lets you build characters for
the [GURPS](http://www.sjgames.com/gurps) 4<sup>th</sup> Edition roleplaying game system.

This repository holds the Master Library data files for the [GCS project](https://github.com/richardwilkes/gcs) — the
traits, skills, spells, equipment, templates, and settings you draw on while building a character, organized by the book
or setting they come from. Most of it was entered by other GCS users and contributed back so that everyone can make use
of it.

## Contributing

If you find a mistake or an omission and have fixed it in your own copy, or you have data files of your own to share,
please send them in. The usual route is a
[Pull Request](https://help.github.com/en/github/collaborating-with-issues-and-pull-requests/creating-a-pull-request-from-a-fork).
If you haven't created one before, a [contributor](https://github.com/rinickolous) to the library recorded
[this short video tutorial](https://www.youtube.com/watch?v=v-sRU0vbxLw) demonstrating the process.

If you can't create a Pull Request for some reason,
[create an Issue](https://github.com/richardwilkes/gcs_master_library/issues/new) instead, attach the file(s)
containing your changes, and explain what it is you changed.

### Page references

When you add page references, use the
[abbreviations from this list](https://gurpscharactersheet.com/page_references.html). If the book you need isn't in the
list yet, please ask what should be used so that the list can be updated appropriately.

## Generative AI Use Policy

Generative AI isn't forbidden in the GURPS Character Sheet project, and you're welcome to use it while preparing a
contribution. If you do, the expectations below apply.

Keep in mind that Generative AI can produce a large amount of error-prone text that takes a long time to check
carefully, and that it can't learn to avoid repeating the same mistake. Library files are normally created and edited
with the GCS application, and are meant to be viewed and edited there rather than as raw text, so errors introduced
into a raw file are easy to overlook and hard to catch in review.

When you submit:

* **Say which parts were AI-generated.** A short note on the Pull Request or Issue is enough.
* **Take as much responsibility for your submission as if you wrote it yourself.** You're expected to have read every
  change, understood all of it, and fixed every error you noticed before asking for review.
* **Open your files in GCS first.** Confirm they load and display correctly in the application.
* **Keep the discussion respectful and on-topic.** The relative merits of Generative AI won't be settled in a discussion
  thread, and we all have to collaborate afterwards.

Please also be aware that maintainers are volunteers. Not wanting to engage with Generative AI is an acceptable reason
for a maintainer to defer your submission to another maintainer, so review may take longer.
